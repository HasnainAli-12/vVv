# Taste
- Prefers responsive, snappy game feel over physically "realistic" tuning: rejects floaty jumps and sluggish animation timing. Confidence: 0.8
- When a task depends on asset naming that isn't obvious, prefers the agent inspect the asset/animation folders itself and pick the right family rather than asking or guessing — points the agent at the folder himself ("check for animations folder, you may have something for it"). Confidence: 0.8
- For character animation, favors reusing the asset pack's existing, convention-matching clip family (e.g. the set that mirrors the established walk/jog structure) instead of introducing out-of-place clips — and expects this for brand-new mechanics too, pointing the agent to the animations folder to find a clip for the new move (e.g. mining the pack's Wall_Climb set for a new ledge-vault state). Confidence: 0.7
- Values short, tight one-shot clips for transient states (e.g. take-off/launch segments) so the state doesn't dominate the overall motion. Confidence: 0.6
- Appreciates visual/camera "juice" that sells motion — e.g. widening the camera FOV during sprint so speed is felt, not just simulated. Confidence: 0.5
- Wants high-fidelity rendering settings and visual polish in the game (e.g. a full URP post-processing volume stack, MSAA, HDR colour grading) — asks for "good graphical settings". Confidence: 0.6
- Expects player mechanics to be strictly gated so they can't be exploited — e.g. one jump per ground contact, no spamming an input to effectively fly, tight coyote/buffer windows. Confidence: 0.55
- Wants levels to have a strong, cohesive themed atmosphere (e.g. dark night, warm red/orange fire-toned lighting, glowing emissive cube edges/corners) rather than plain, unstyled geometry. Confidence: 0.6
- Weighs readability over atmosphere when the two conflict: a dark/night scene is fine only while the level is still easy to see, so when it gets "too dark to see anything properly" wants overall lighting/mood lifted (ambient, key light, exposure) rather than the dark look preserved. Confidence: 0.5
- Treats audio as part of the game's polish, not an afterthought: expects looping background music in the scene bed plus character SFX wired to gameplay (jump/land, footsteps, swing, slide). Confidence: 0.6
- Expects newly added model props to be fully wired up with the right textures/materials (albedo, normal, emission) so they render correctly — considers fixing import issues (wrong scale, unassigned maps, wrong texture type) part of the agent's job, and expects imported third-party models to be cleaned of the authoring junk they ship with (stray cameras/lights, odd root nodes) at the importer settings level so a reimport can't reintroduce them. Confidence: 0.65
- Keeps the player character clean of non-visual components: objects parented to the character (attached props like a sword on the back) should be visual-only — rejects extra cameras and lights riding along with them ("stop adding the two light points to the player"). Confidence: 0.6
- For level layout, wants an overall linear progression — one start-to-finish route with no loops or revisiting — but winding, with turns and elevation changes rather than one straight corridor (explicitly rejected both a circular/loop layout and a purely straight path). Confidence: 0.85
- Wants dedicated large open combat arenas ("pits") for enemy fights distributed along the level (at least ~3), each kept clear in the centre with room to fight rather than being a dense obstacle course; each with multiple entry/exit points and only a few large cover pieces so the player is never cornered. Confidence: 0.7
- Wants decorative set-piece props (e.g. tornadoes, torches) as visible aesthetic landmarks — multiple instances at varied sizes — placed so they never interfere with the player's route. Confidence: 0.6
- Prefers scoping Unity gameplay interactions with dedicated layers/tags (e.g. a `WallRun` layer only those walls carry, probe mask restricted to it) instead of letting a mechanic react to arbitrary geometry — suggested this himself when detection was "too reactive". Confidence: 0.6
- For traversal mechanics (e.g. wall-run detection), favors implementations that preserve level-design freedom — points to collision-based detection with vector math (e.g. `OnCollisionEnter()` plus checks that the player isn't atop/beneath the surface) over raycast fans or requiring every runnable surface to be tagged/layered, since those limit either the kinds of wall runs possible or the geometry itself (rejects solutions where a wall can be run on but not also stood atop). Confidence: 0.5
- For level design, wants a free-running feel (Mirror's Edge / Tachyon Flow style): continuous momentum across large, wide surfaces (decks, walkways, ramps) with obstacles standing ON the route — explicitly rejects a parkour obstacle course of small precision-hop platforms with gaps everywhere ("the platforms are too small and more of a parkour game instead of free running game"). Confidence: 0.85

- Wants deliberate scale contrast in levels — massive architecture and huge open spaces balanced against tighter corridors; explicitly rejects everything being the same size. Confidence: 0.7
- For traversal mechanics, wants transitions (e.g. the wall jump) to ADD to the momentum carried in rather than replace it — the jump should apply forward acceleration on top of the current speed so it extends the run, not interrupt it — and any push away from the surface kept minimal relative to a sideways launch ("just a little bit to get out of range"), not a big shove. Confidence: 0.7
- The "little bit" of away-push is measured against the mechanic's own detection range, not taste: rejects tuning values that don't actually agree with each other, i.e. a push small enough that the cooldown expires while the player is still inside probe range and re-sticks to the same wall ("still, need more distance from the wall, it sticks back to the wall again"). Expects the push speed, probe distance and re-grab cooldown to be checked as one coupled set rather than adjusted in isolation. Confidence: 0.7
- Will not accept a re-grab of the wall the player just left, even after the numbers are reconciled: a cooldown that merely delays the re-grab is not good enough — wants the same wall blocked outright until the player lands (explicitly "I don't want regrabs"). Directional blocking is fine so a deliberate chain onto an opposing wall still works. Confidence: 0.8
- For traversal moves, wants distance/range to be generous rather than default-small: launches sized to actually cover the level's gaps, and slides asked to be lengthened outright ("increase slide distance"). Expects the range levers to be reasoned about together — e.g. for a launch, forward speed cap and upward speed both matter because reach = forward speed × airtime. Confidence: 0.7
- Wants a structured, paced course arc rather than a flat sequence: easy tutorial intro → build-up of combined obstacles → combat arena → harder traversal → combat arena → fast combined-move climax → final boss arena (the largest, most dramatic space) that the whole course builds up to. Alternates high-intensity movement and calm "breathing" stretches, with a total target playtime budget (~4-5 min). Confidence: 0.65
